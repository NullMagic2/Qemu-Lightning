Module: lightning.direct3d12_umd.build_instructions
Purpose: Reproduce the Windows adapter and selected Venus capability bridge.
Created: 2026-10-24
Architecture: Rust owns bounded adapter/backend policy. Thin C uses genuine WDK,
Win32 and Vulkan structures. This module never installs or advertises a device.

Implementation
    OpenAdapter12 exports the official R0/0003 WDK adapter table. It copies the
    runtime callback and its opaque selected adapter handle, without loading any
    backend. The runtime must keep callback code valid until CloseAdapter succeeds.

    QemuLightningInternalOpenNativeAdapterR0(version=1) opens an explicit private
    profile on the same adapter machinery. pfnGetSupportedVersions reports exactly
    D3D12DDI_SUPPORTED_0003 for that profile. Its genuine core, 3D list and 3D queue
    tables support the selected copy, compute and draw paths through the existing
    owner registries. Other table types and out-of-scope slots remain unavailable.
    The single list table is installed at index zero with its runtime handle.
    Successful CreateCommandList publishes the runtime-owned list and then calls
    the copied SetCommandListDDITableCb under a generation-scoped device lease.
    Scoped recording errors use SetCommandListErrorCb with that list's exact
    runtime handle. Core and queue failures keep using the device SetErrorCb.
    Core allocation slots route committed buffers and render-target images to their
    typed owning implementation. Scoped RGBA8/BGRA8/RGB10A2/RGBA16_FLOAT/RGBA16_UNORM render-target and sample-one queries
    check actual selected Vulkan image requirements. The ICD can decline the format.
    Managed fences still use the existing private fence preparation and attachment.
    Public discovery continues to report zero DDI versions. Windows resource/KMD
    association, the full feature-level contract, mandatory slots and DXGI remain open.

    The opt-in R0 version 2 adds real WDDM queue ownership through the four
    required virtual-context and paging-queue callbacks in the runtime's R0
    core layer. A command queue obtains its context on the selected render
    node before its cookie becomes visible. QemuLightningInternalPrepareNativePagingQueue
    explicitly obtains the paging queue and its monitored fence for a live
    queue. Returned handles remain borrowed through the queue lifetime.
    The paging queue is optional per queue and is destroyed before its context.
    If either destroy callback fails, the private runtime retains the queue
    storage and runtime handle and retries RetireCommandQueue. New work stops
    after retirement is requested. Version 1 continues to accept its original
    callback set and leaves WDDM queue creation to the caller.
    The opt-in R0 version 3 adds WDDM allocation association for the scoped
    committed RGBA8/BGRA8/RGB10A2/RGBA16_FLOAT/RGBA16_UNORM render target. It requires both runtime allocation
    callbacks and VK_KHR_external_memory_win32 on the selected Lightning ICD.
    The image format query must permit the opaque Win32 export. The paired
    ICD exports a Venus backing ID for the bound dedicated allocation. The
    runtime AllocateCb gives the miniport its own reference to that ID.
    CheckResourceAllocationHandle returns the D3DKMT allocation for a live
    image in the owning device. Retirement calls DeallocateCb before freeing
    Vulkan memory and retains the owner if the callback has to be retried.
    The private profile still needs other resource coverage, GPUVA mapping,
    VidMm residency, and WDDM command scheduling.

    Private native committed RGBA8/BGRA8/RGB10A2/RGBA16_FLOAT/RGBA16_UNORM render targets accept nonempty dimensions
    within the guest cap, selected framebuffer and image-format limits, and
    allocation size and alignment restrictions. Format support probes the
    smallest nonempty shape. RTVs, clear and draw submissions, upload/readback
    and presentation use the exact admitted extent and format. Draw requires
    a matching graphics PSO and RTV format. A copy footprint must match the
    retained image format and geometry and cover each row's active bytes.
    Texture1D render targets require Height=1 and use actual Vulkan 1D
    images and views, with independent selected image-type and format limits.
    Texture1D and Texture2D arrays use the selected Vulkan layer limit and the
    total backing size. Initialization clears all layers. An RTV can clear
    a contiguous range within the framebuffer layer limit. A draw without a layer output uses the first
    layer of its bound RTV range, and a transfer uses one subresource with matching single-layer
    or explicit all-layer barriers. Texture1D transfers use one row.
    Texture3D uses a genuine Vulkan 3D image and checks the selected format's
    width, height, depth and backing size limits. RTVs select W slices of mip
    zero. Clears can span a slice range, while a draw without a layer output uses the first selected slice. Vulkan
    barriers cover the entire volume mip. Pitched transfers copy that entire
    mip and use SlicePitch between depth slices.
    The private color path admits 2, 4, 8 or 16 samples on Texture2D when
    selected framebuffer and format sample masks both support the count.
    Graphics PSOs and RTVs must have identical sample counts. Raw pitched
    buffer copies require one sample.
    QemuLightningInternalRecordNativeColorResolve records a whole-layer
    multisample-to-single-sample resolve on an empty render-target list.
    Both images enter and leave in RENDER_TARGET and stay retained until
    actual completion or safe drain. Public Windows resolve DDI remains open.
    Private window presentation accepts single-sample, single-layer
    Texture1D and Texture2D.
    Pitched copies use eight bytes per RGBA16 texel and four bytes
    per texel for the other formats. RGBA16_FLOAT clears accept finite
    values within the half-float range, including negative and above-one
    channels. Its private presentation path converts to an SDR swapchain.

    QemuLightningInternalQueryMemoryBudget reads a live per-VM blob limit and
    charged usage through the runtime's selected adapter and a matching Venus
    host. The versioned result includes the negotiated CPU aperture and a
    separate, per-heap tally of live UMD buffer and image allocation bytes.
    The selected Vulkan driver can supply its optional live per-heap budget
    and usage. Older hosts without the negotiated query return unsupported.
    Public DXGI budget and residency are outside this private interface.

    The opt-in R0 pfnGetCaps handles the genuine memory-architecture schema
    for node zero when the selected ICD exhibits the implemented discrete
    host and local pool split. UMA and adapter-wide coherency remain unadvertised.

    Official pfnGetCaps handles exact D3D12DDI_SHADER_CAPS_0003 output and the
    genuine D3D12DDI_D3D12_SHADER_MODELS_DATA_0011 pointer/count protocol. Rust
    intersects physical evidence with implemented native shader features. No
    optional shader features or translated models exist yet: feature fields are
    false, model count is zero, and caller model arrays remain untouched. A null
    model array performs a count-only query; null/aliased count storage, wrapped
    array ranges and wrong schema sizes fail without output mutation. Queries
    never load the backend or call the runtime. Shader negotiation succeeds even
    without a Vulkan dependency, but cannot advertise a usable device or model.
    Unknown cap types, mandatory D3D12 options, pipeline levels, GPU VA and other
    schema versions remain unsupported. The source policy
    and exact supported native layouts are listed in native-caps-policy.json.

    QemuLightningInternalQueryBackendSnapshot is an explicitly PRIVATE observation
    API. Its signature is declared for fixture consumers as QUERY_BACKEND; it takes
    an official D3D12DDI_HADAPTER, exact generated snapshot byte size and writable
    QLDX12_BACKEND_SNAPSHOT pointer. Call it outside DllMain and loader-lock contexts
    while holding the UMD module loaded. It does not create a D3D12 device.

    First valid query uses that adapter's official QueryAdapterInfoCb for the
    existing 32-byte QLGA contract and the distinct 48-byte selected identity reply.
    The shared Rust contract/generator owns both schemas. Old KMDs reject identity48
    and initialization fails; the UMD never derives a LUID from opaque handle bits.

    Only verified exact sibling vulkan-1.dll and QemuLightningVulkan.dll modules
    are accepted. VK_LUNARG_direct_driver_loading is EXCLUSIVE, with one ICD and no
    Vulkan environment or registry mutation. The instance requires Vulkan1.3.
    Exactly one non-CPU Lightning physical device must match the selected OS LUID
    and single-node mask. A second adapter, mismatch, duplicate, invalid identity,
    overflow count or VK_INCOMPLETE fails; there is no fallback to another GPU.

    The immutable scalar snapshot records raw physical API, feature-chain booleans,
    limits, queue counts and physical device-local heap bytes. Its usable 2D limit
    is min(physical maximum, the paired guest contract maximum of 4096). Physical
    heap bytes are not the guest allocation budget, residency or application budget.
    A reserved alignment word is zero, and generated Rust/C field-offset checks
    cover the entire layout. No official Vulkan or D3D ABI is redefined in Rust.

    QemuLightningInternalQueryBackendRequirement returns one exact-size private
    QLDX12_REQUIREMENT_RESULT for a named rule index in requirements_contract.h.
    requirements-source.json maps all23 rules to immutable proposed vkd3d-proton
    v2.14 source hashes/branches or explicit guest/native gaps. Hard/conditional
    failures and advisory/optional absences remain separate. The descriptor-buffer
    alternative is unobserved until runtime initialization; UBO descriptor limits
    are not imposed because upstream permits SSBO fallback. Passing the selected
    startup inventory does not prove queues, formats, device feature-enable chains,
    descriptor layouts, logical-device creation, native DDI devices or FL11_0.
    profile_complete/native_ddi_implemented remain zero. No translator is linked.

    QemuLightningInternalEnumerateBackendExtensions returns normalized names and
    actual spec versions from the cached selected physical device. Pass exact
    sizeof(QLDX12_BACKEND_EXTENSION), a start index and count capacity. A null
    array requires input count0 and returns remaining count. Array calls copy at
    most8 entries per page and return DXGI_ERROR_MORE_DATA while entries remain.
    Zero-capacity pages are valid. Count storage and output arrays cannot overlap.
    Invalid/busy/stale/backend failures preserve outputs; MORE_DATA publishes a
    complete valid page. Duplicate, unterminated, invalid ASCII identifiers and
    zero spec versions fail before evidence is published. Tests use modeled ICDs.

    The separate experimental native fence bundle owns local/imported Windows
    monitored-fence mappings through PrepareFence before the genuine R0 CreateFence
    validates the exact GPU VA. AttachQueue enables bounded asynchronous waits,
    signals and deferred native ExecuteCommandLists. CPU signals use genuine KMT
    notification; asynchronous OS wait events preserve intermediate values across
    rewinds. Shared NT handles can be exported and imported with independent KMT
    ownership. Arbitrary unregistered runtime GPU VAs are declined, never treated
    as CPU pointers. This is source implementation behind the existing public gate;
    the default WDDM1.3 package and full D3D12 advertisement remain unchanged.

    The private native fence bundle version 2 extends its original function
    prefix with application completion events and a device-removal query.
    Pass the exact QLDX12_NATIVE_FENCE_COMPLETION_FUNCTIONS byte size.
    A non-null Win32 event is duplicated and signaled after the KMT target
    is reached or the owning device is removed. A null handle blocks until
    the target is reached or returns the removal HRESULT. Loss drains
    registrations without signaling the shared KMT fence value. A fence
    with pending registrations owns its mapping until they are released.
    Version 1 keeps its original layout. Retained native fence waits sample
    D3DKMTGetDeviceState on their exact KMT device, and a signaled event
    requires a fresh active execution result before it counts as progress.
    A confirmed reset/removal wakes the old waiters and enters normal loss
    teardown. Pending or failed state queries leave the event and ownership
    outstanding, including a removal sentinel without confirmed loss.

    QemuLightningInternalRetireLostNativeDevice tears down a confirmed-removed
    device and its driver-owned children using retained generation keys. It
    drains presentation targets and accepted queues before retiring lists,
    resource descriptors, pipeline state, buffers, images and allocators.
    Stale child storage is never read. A live CPU map or failed host drain
    keeps the blocking owners and device available for retry. The void
    DestroyDevice callback uses the same path for a confirmed-removed device.
    Call outside loader-lock contexts while the runtime device is still live.

    The D5 private native presentation exports are declared in native_present.h.
    PresentNativeImage accepts an initialized native render-target image, its
    owning DDI device, a live same-process HWND and an interval of zero or one.
    The exact selected ICD must support Win32 surface and swapchain extensions.
    Venus WSI owns the swapchain. The selected Vulkan queue blits the rendered
    image into an acquired buffer and restores its attachment layout. FIFO at
    interval one and immediate mode at interval zero require surface support.
    PresentNativeImageOnQueue binds each HWND to an exact DIRECT queue and
    returns busy while earlier list execution or logical fence work is pending.
    A busy in-flight frame keeps its source and queue until a matching retry or
    safe retirement. Later scheduled work on the reserved queue stays ordered.
    The original PresentNativeImage entry point still accepts caller-completed
    rendering. Up to eight windows per selected adapter own separate swapchains.
    RetireNativePresentationWindow releases one. The original retire export
    releases all targets owned by the device. Failed drains remain retryable.
    Public DXGI backbuffers, Present DDI, shared resources and output transitions
    require the complete runtime interfaces.

    The build provides backend_present_fixture.exe for modeled WSI behavior
    and native_present_fixture.exe for a signed-in Windows guest with the exact
    production loader and ICD. The native fixture uses real KMT adapter queries,
    submits real RTV clears, checks two independent window swapchains with
    FIFO and immediate presentation, then verifies resize and independent
    queue/target retirement. The modeled variant verifies that a DIRECT
    fence wait gates presentation and a failed handoff releases later work.

    build.rs also builds a distinct fence-modeled fixture DLL. Its KMT loader is
    explicitly modeled while actual production ownership, worker, DDI normalization
    and OS structure marshalling execute. Passing it does not establish native
    Windows notification, cross-process/API sharing or real GPU acceptance.

Lifetime
    A short official SRW lock protects the Rust registry only; callbacks, module
    loading, Vulkan operations and destruction all execute outside that lock.
    Success/failure is cached per adapter. Loading queries return busy on reentry.
    CloseAdapter returns DXGI_ERROR_WAS_STILL_DRAWING while loading; retry after
    the active query completes. A successful close detaches ownership exactly once,
    destroys any successfully drained device/queue owner, then VkInstance, then
    releases ICD/loader references and runtime context.
    No callback is used after successful close. Stale identities never alias reuse.
    Device initialization uses QemuLightningInternalInitializeBackendDevice with
    an exact-size QLDX12_DEVICE_RESULT. The separate device-policy.json names all
    fourteen enabled feature bits, two extensions and conservative admission.
    Rust requires the checked hard/conventional prerequisite profile plus timeline,
    buffer-address, sync2, dynamic-rendering and robust-buffer features. It chooses
    the first nonempty graphics+compute family; no descriptor-buffer alternative
    or fallback GPU is substituted. Official Vulkan structures enable only that
    subset, one priority1.0 queue and a zero-initialized real timeline semaphore.
    Win32 WSI can add the optional VK_KHR_swapchain extension when the exact
    ICD advertises the corresponding instance and device support.
    This is not full vkd3d initialization, a native DDI device or FL11_0.

    QemuLightningInternalBackendQueueOperation accepts a copied exact-version
    QLDX12_QUEUE_COMMAND and exact-size QLDX12_QUEUE_REPORT. SIGNAL submits actual
    empty vkQueueSubmit2 work with a private increasing timeline value. One pending
    unobserved signal is allowed; QUERY reads the actual counter and WAIT uses a
    caller-selected submitted target with at most10ms timeout. Timeout returns
    DXGI_ERROR_WAIT_TIMEOUT and leaves report output unchanged. Other operation
    failures retain their HRESULT and fault later queue use, including signals
    accepted before a failed counter read. No rendering or OS fence follows.
    Malformed commands perform no queue operation or output publication, but may
    lazily initialize the backend/device before QueueState validates their shape.

    Separate initializing/operating/retiring states prevent close or concurrent
    external queue work. Close keeps the adapter slot pinned while draining outside
    the SRW lock. After any submission attempt, successful QueueWaitIdle or confirmed
    device loss permits semaphore/device destruction; other errors retain all
    ownership for a retry. Only after successful device retirement does close detach
    and release instance/modules/runtime. Callback lifetime extends to that point.
    The logical-device requirement reports actual per-adapter initialized ownership,
    while profile_complete/native_ddi_implemented remain zero.

    Private buffer APIs create/destroy backend tokens and copy bounded host bytes:
    QemuLightningInternalCreateBackendBuffer takes copied QLDX12_BUFFER_COMMAND
    and exact-size QLDX12_BUFFER_RESULT. DEFAULT requires physical DEVICE_LOCAL;
    UPLOAD and READBACK require HOST_VISIBLE|HOST_COHERENT, with HOST_CACHED
    preferred for readback. Unsupported additional memory flags (protected,
    lazy, vendor-specific) are never selected. Memory type bits, heap indices,
    heap sizes and maxMemoryAllocationCount come from the selected real device.
    Requirements2 is queried with dedicated requirements, and every allocation
    is dedicated to its buffer, bound at offset0. No buffer-device-address usage
    or allocation flag is requested. Physical memory is not a guest budget.

    Rust limits each adapter to32 live buffers, each request to64MiB, individual
    observed allocation to128MiB and aggregate observed allocation to256MiB.
    These are implementation quotas, not capability/budget claims. Result records
    requested bytes separately from actual allocation size. Failure rolls back
    buffer/memory ownership and quota. Fresh tokens are unique across adapters;
    destroy invalidates a token and returns its actual allocation charge.

    QemuLightningInternalWriteBackendBuffer permits only UPLOAD; the Read variant
    permits only READBACK. Each call checks overflow/range and <=64KiB, stages host
    bytes in bounded heap storage, maps the whole coherent allocation temporarily,
    copies, unmaps and only then publishes read output. DEFAULT cannot map through
    this API. No pointer or Vulkan handle escapes; failed reads preserve bytes.
    Noncoherent-only memory is rejected. Map is not a GPU completion operation.

    The device operation lease excludes creation/copy/destroy/queue/close races.
    Current empty queue submissions reference no buffers. Future GPU resource use
    must add usage/completion synchronization before extending CPU access or
    destruction. Close first drains the queue; failed drain retains every live
    buffer/memory/device. After successful drain, all buffers are destroyed before
    freeing memory and the device, then instance/modules/runtime. No D3D12 heap,
    native resource callback or residency/guest budget is implemented here.

    Immutable extension storage is retained inside the backend. Bounded Rust reader
    leases prevent successful close while C inventory memory is read outside the
    registry lock. Reports evaluate copied cached Rust scalars without C callbacks.

Build prerequisites
    Host Rust compiler supporting edition2024; Windows Rust compiler with target
    x86_64-pc-windows-gnu; sha256sum; restored official WDK/SDK10.0.28000.0 and
    clang-cl-21/lld-link-21 in the existing WDDM_TOOLCHAIN layout.
    VULKAN_HEADERS_INCLUDE points to existing Vulkan-Headers v1.4.335 include/.
    The consumed sixteen generated header files must match vulkan-headers.sha256.
    Official release metadata: https://github.com/KhronosGroup/Vulkan-Headers/releases/tag/v1.4.335
    Local vendored bytes are pinned; the builder downloads no dependencies.
    GRAPHICS_SOURCE_ROOT optionally names a source root containing the paired shared
    graphics adapter generator and miniport allocation policy generator.
    Default: the source tree above lightning/.

Build (all placeholders are explicit absolute paths)
    rustc --edition=2024 SOURCE_DIRECTORY/build.rs -o PRIVATE_OUTPUT/dx12-build
    WDDM_TOOLCHAIN=OFFICIAL_KIT VULKAN_HEADERS_INCLUDE=PINNED_INCLUDE \
    RUSTC_WINDOWS=WINDOWS_TARGET_RUSTC GRAPHICS_SOURCE_ROOT=PAIRED_SOURCE_ROOT \
        PRIVATE_OUTPUT/dx12-build SOURCE_DIRECTORY PRIVATE_OUTPUT/artifacts

    SOURCE_DIRECTORY is lightning/direct3d12-umd. The first output folder must exist.
    production/ contains the actual bootstrap DLL and independent ABI fixture.
    modeled/ contains a copy plus backend fixture and explicitly synthetic sibling
    loader/ICD DLLs. Never package these test dependencies as the production backend.
    missing-dependency/ contains only the modeled loader: the missing exact ICD must
    cause failure and release that partially loaded module. No system fallback occurs.
    Build output is never published to canonical Binaries; no INF is changed.

Validation
    Run production/adapter_abi_fixture.exe, modeled/backend_fixture.exe,
    modeled/requirements_fixture.exe, modeled/device_fixture.exe,
    modeled/buffer_fixture.exe and
    missing-dependency/backend_fixture.exe under Windows or an explicitly isolated
    Wine prefix. Tests exercise actual production exports with official WDK/Vulkan
    function types, plus separately labeled modeled dependencies. Scenarios include
    independent ownership, stale identities, simultaneous close, cached query states,
    mismatched/ambiguous/CPU adapters, incomplete and growing enumerations, missing
    functions, malformed kernel identity, reentrant callbacks and close while busy.
    The adapter fixture exercises exact official native shader layouts, negative
    support, count/array output preservation, alias/overflow rejection and confirms
    no callback/backend I/O occurs. The device fixture separately observes physical
    shaderFloat64=true and verifies this never enables native Doubles or a shader
    model, before and after selected Vulkan device initialization.
    The device fixture inspects the exact official enable chain, selected family,
    two independent device/timeline owners, partial creation/function-load cleanup,
    cached failures, pending completion/timeout, failed drain/retry and blocked
    creation/submission races with close. Synthetic ICDs never access a GPU.

    These modeled tests do not execute real Venus, access a GPU, validate native
    Windows runtime acceptance or implement a D3D12 translation backend. A real
    Windows selected-adapter run remains pending. F2.5 and D1 remain partial; no
    complete native D3D12 behavior unit follows. Supported device versions remain
    empty, and native device/table requests remain rejected. Only the two shader
    capability protocols above succeed with explicit empty native support. Testing
    contributes zero implementation progress.

Native vertex Layer output requires rebuilding the pinned QemuLightningShader.dll with shader_dependency.rs; the additive QemuLightningShaderNativeGetFeatures export must be present. Older ABI2 compilers retain the previous resource-free shader subset. No complete native shader model or feature level is advertised by this optional extension.

Explicit capability diagnostics: QemuLightningInternalQueryNativeCapabilityStatus uses version1 and the generated native_caps_contract.h record. It distinguishes physical host requirements, effective guest limits, pinned bounded native stage support and unavailable mandatory native levels/tiers. The report creates no Vulkan device or GPU work and changes no public interface advertisement. Official GetCaps does not load the compiler.

F4 runtime execution status uses the copied native CreateDevice pKTCallbacks.pfnEscapeCb. DeviceStatusQuery supplies the real retained adapter/device handles and never creates a KMT fence or Vulkan device. Existing queue/fence workers pace probes at32ms; explicit removal queries can probe a device without fences. Failed/pending queries do not confirm removal, and all runtime calls stay outside the policy lock under exact-generation leases. Full native public runtime qualification and hibernation are not implied.

    association and additionally binds supported committed DEFAULT and custom
    cached coherent UPLOAD/READBACK buffers to actual device-owned WDDM
    allocations. Profiles1-3 keep their existing buffer behavior.
    The matching Vulkan usage must report external-memory export support.

    initialization and a final parent fault check precede cookie publication.

    from exact live runtime storage generations.
    This does not advertise public DX12 readiness, GPUVA, residency or scheduling.
    Native Windows qualification and public runtime integration remain pending.
